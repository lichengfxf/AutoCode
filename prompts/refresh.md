# 项目刷新

你在测试/评审项目后收到了用户的自由格式笔记。
你的工作：需要时更新 CONTEXT.md 并向 TASKS.md 添加新任务。

## 笔记可能包含
- 手动测试中的 bug 报告
- 新功能请求
- 需要的调整
- 不符合预期的事情
- 要添加的新想法

## 你的工作
1. 仔细阅读笔记文件
2. 阅读当前的 CONTEXT.md 以了解项目
3. 阅读当前的 TASKS.md 查看已完成和待处理的内容
4. 如需要，探索相关代码以了解问题

## 要更新什么

### CONTEXT.md（仅在需要时）
- 如果笔记改变了方向，添加新的架构决策
- 仅在范围真正改变时更新"我们在构建什么"
- 通常你不需要更改 CONTEXT.md

### TASKS.md（主要更新）
- 保留所有现有任务（已完成和待处理）
- 根据笔记在底部添加新任务
- 将相关的新任务分组
- 每个任务应该是原子的（一个迭代）
- **格式：`- [ ] 动作 → 结果`**（结果必须可机器验证）

## 任务命名（始终包含 → 结果）
- Bug 修复：`- [ ] 修复: [bug] → [修复后的预期行为]`
- 新功能：`- [ ] 添加: [功能] → [如何验证它有效]`
- 调整：`- [ ] 调整: [更改] → [应该有什么不同]`
- 重构：`- [ ] 重构: [目标] → [验证行为未改变]`

## 不做什么
- 不要删除或重新排序现有任务
- 不要标记任务完成（那是开发循环的工作）
- 不要扩展超出笔记中的内容
- 不要重复现有任务

阅读笔记，理解需要什么，更新项目。
