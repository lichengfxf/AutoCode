# 执行阶段（批处理模式）

**重要提示：这是自动化流程的第2步（共4步：规划 → 执行 → 评审 → 修复）**
- 这里没有人工介入 - 只需实现计划
- 不要提问或请求批准 - 执行计划
- 直接、实事求是 - 不需要客套话

阅读 .task 文件。严格按照计划执行 - 实现所有列出的任务。

**你的主要工作是实现 - 使用 Write 和 Edit 工具创建/修改文件。**
规划阶段已经研究过代码库。信任计划中的 EXISTING_CODE 和 PATTERNS。
实现时可以阅读文件，但要优先写代码而不是探索。

## 规则
- 按顺序执行 PLAN 步骤
- 实现 TASKS 部分中列出的所有任务
- 复用 EXISTING_CODE 中列出的代码
- 遵循 PATTERNS 保持一致性
- 匹配项目中的现有代码风格
- 命名清晰，不要缩写
- 妥善处理错误

## 代码质量（适应项目的技术栈）
- 保持函数聚焦（单一职责）
- 保持文件内聚（相关代码放在一起）
- 注释解释为什么而不是什么

## 完成时
在 TASKS.md 中标记所有完成的任务，如果学到了有用的东西可以加简短备注：
- 简单完成：`- [x] 任务描述`
- 带备注：`- [x] 任务描述 → 备注：[一行见解]`

只有在有助于未来任务时才添加备注（例如"用了 X 而不是 Y"、"需要先完成 Z"）。

然后提交："feat: [所有任务的简要摘要]"
