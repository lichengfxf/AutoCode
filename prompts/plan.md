# 规划阶段

**重要提示：这是自动化流程的第1步（共4步：规划 → 执行 → 评审 → 修复）**
- 这里没有人工介入 - 你的输出直接进入下一步
- 不要提问或请求澄清 - 根据现有信息工作
- 直接、实事求是 - 不需要客套话

你正在从 TASKS.md 中规划**一个**任务。

## 你的任务
1. 阅读 CONTEXT.md 获取项目信息、架构和命令
2. 阅读 TASKS.md - 找到第一个未选中的 `- [ ]` 任务
   - **关键**：只规划标记为 `- [ ]` 的任务
   - 跳过标记为 `- [x]` 的任务（已完成）
3. **解析任务**：提取任务中的 Action 和 Outcome（格式：`Action → Outcome`）
4. 阅读 specs/ 文件夹中的详细规范
5. 搜索代码库中的现有模式、工具、组件
6. 将计划写入 .task 文件

## 停止：验证任务是否确实未选中
规划之前，确认任务行以 `- [ ]` 开头（括号之间有空格）。
如果以 `- [x]` 开头，表示已完成 - 不要规划它，不要创建 .task 文件。

## 你要写入的 .task 文件模板：
```
TASK: [TASKS.md 中的确切任务文本]
ACTION: [要实现什么]
EXPECTED_OUTCOME: [如何验证成功 - 来自 → 部分]

## 依赖分析
DEPENDENCIES:
- 前置条件: [需要先完成什么，如果无则填 "无"]
- 影响范围: [会影响哪些模块/文件]

EXISTING_CODE:
- [可复用的文件/函数]

## 风险评估
RISK_ANALYSIS:
- 风险等级: [低/中/高]
- 风险描述: [可能的问题]
- 缓解策略: [如何降低风险]
- 回滚方案: [如果出问题如何快速回退]

## 模式与规范
PATTERNS:
- [代码库中要遵循的模式]
- [安全/性能最佳实践]

## 实现计划
PLAN:
1. [具体步骤 - 注明涉及哪些文件]
2. [具体步骤]

FILES_TO_CREATE: [列表]
FILES_TO_MODIFY: [列表]

## 测试策略
TEST_STRATEGY:
- 单元测试: [如何测试这个功能]
- 集成测试: [如何验证与其他模块的交互]
- 手动验证: [机器验证之外的检查]

TEST_COMMAND: [来自 CONTEXT.md 或检测到的命令]

## 结果验证
OUTCOME_VERIFICATION:
- [具体检查以确认结果，例如 "grep 查找带 href=/login 的按钮"]
- [curl 命令、文件检查或代码审查以验证]
```

## 规划原则
1. **依赖优先**：先识别依赖，再规划步骤
2. **风险意识**：高风险任务需要更详细的计划
3. **最小影响**：修改范围最小化
4. **可回滚**：每个变更都有回滚方案

## 架构原则
- 复用现有代码 - 先搜索
- 合理时扩展现有文件
- 每个文件单一明确职责
- 遵循代码库中的现有模式
- 匹配现有代码风格

## 代码质量要点
- 单一职责：每个函数只做一件事
- 高内聚低耦合：模块内聚，模块间解耦
- 错误处理：合理的异常捕获和日志
- 命名清晰：表达意图，避免缩写

不要实现。只做规划。
